# Producer fixtures

Facts the JavaScript producer and the Kotlin modules must agree on, written once and read by both.
A fixture that only one side reads is a copy, and copies are what drift.

| File | Read by (JS) | Read by (Kotlin) |
|---|---|---|
| `frames/*.json` | `test/fixtures.test.js` | `ProducerFramesTest`, `:inspector-model` jvmTest |
| `defaults.json` | `test/defaults.test.js` | `ProducerDefaultsTest`, `:inspector-core` jvmTest |
| `emulator-profiles.json` | `test/emulator.test.js` | `EmulatorDetectionTest`, `:inspector-stream` testAndroidHostTest |

Every reader fails when it finds nothing to read. Each Gradle task declares this folder an
`@InputDirectory`, so an edit here re-runs the Kotlin tests with no rerun flag.

## `frames/*.json`

```json
{ "scenario": { "about": "…", "start": { …start() config… }, "steps": [ … ] },
  "frames": [ <WireMsg>, … ] }
```

`fixtures.test.js` starts a fresh producer with `scenario.start`, opens the socket, acknowledges
with session `s1`, runs the steps, flushes, and requires the frames it sent to equal `frames`,
compared parsed, in order, none missing and none extra. The clock and ids are deterministic: ids
count up from `00000000`, and `ts` is `2026-10-30T12:00:00.000Z`.

A step sets the clock and sends one signal:

- `{"now": 1500.75, "signal": ["tag", "name"], "data": <any JSON>}` sends `data` as the payload;
- without `data`, the signal has no payload, and `"data": null` is the payload `null`;
- `"dataText": {"repeat": "a", "times": 65534, "then": "éz"}` builds a long string payload, so a
  payload past the 64 KB cap is written out once, in the frame, rather than twice.

`ProducerFramesTest` decodes every frame as a `WireMsg` with unknown keys **refused**, then checks
what the serializer cannot: an 8-character lowercase hex `id`, `v` present on `client`, `signal`
and `txn`, a known `Platforms` and `BodyOmission` value, and an integer `mono` of at least 0.

Expected frames were generated by running the scenario once and then checked by hand, sizes and
base64 against Node's `Buffer`. When the producer's output changes on purpose, regenerate them the
same way and read the diff before keeping it.

## `defaults.json`

`InspectorConfig()`'s `captureContentTypes`, `bodyCaptureMaxBytes` and `signals.maxPayloadBytes`,
and `contentTypeCases`: a content type and whether `capturesBody` keeps its body under the default
config (prefix match, plus the `+json` and `+xml` suffixes; `null` is not captured). The core
embeds only the payload cap; the allowlist and the body cap belong to the capture file.

## `emulator-profiles.json`

One entry per Android image, with all seven `Build` fields Kotlin reads and the answer each runner
must give: `expect.kotlin` for `looksLikeEmulator`, `expect.js` for the producer's rule, which
sees only `Fingerprint`, `Model` and `Brand`. Where the two differ, `jsReason` says why.

`provenance` says where the values came from:

- `transcribed`: read off a booted image with `adb shell getprop`. Add a real one when a new
  image family appears;
- `representative`: plausible vendor values, not read off hardware, because no phone has been
  attached. They pin that nothing fires on a field a shipping phone carries;
- `constructed`: not an image at all, but a case built to isolate one rule or the empty answer.
