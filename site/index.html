Inspector is a network inspector for Compose Multiplatform apps. One capture feeds an in-app overlay, a local web UI with a searchable archive, and an MCP server your coding agent can query. It is debug-only by construction, so none of it can end up in a release build.

Four surfaces, one capture

Read the same traffic wherever you're working

A row in the overlay, a row in the browser and a row an agent reads are the same record. A filter you type on the phone is a string you can hand to an agent.

In-app overlay

A draggable pill shows the latest call. Tap it and you get the full inspector, from one Compose codebase on Android, iOS and desktop.

  • One row per attempt, so redirects and retries are never collapsed
  • Foldable JSON tree, headers, cURL copy
  • Markers and app state on the same timeline
127.0.0.1:8099

Web UI localhost

Every session is archived, and you can browse it at 127.0.0.1:8099, live or long after the app has closed.

  • Filter grammar: status:4xx path:/checkout since:marker("pay")
  • Replay a call, edited or re-signed by the app
  • Export a whole session as HTML, Markdown, JSON or HAR

MCP server for agents

Your coding agent reads the same archive you do. It starts with a one-kilobyte summary and pulls only the bodies it needs.

  • session_summary, list_transactions, get_body, explain, timeline, export_session
  • Agents can drop markers and pull live app state
  • Failures come back as readable results the agent can correct from, not dead ends

Local daemon & archive

A small JVM daemon that runs on your machine and nowhere else. Sessions are plain folders and jsonl files you can grep, diff and attach to a bug report.

  • Binds to loopback only, never to the network
  • Retention by count and by size
  • Bridges a USB-attached iPhone, with nothing to configure

New in 1.3.0

Follow the user from screen to screen

The path tab draws the route through the app as a line of stations, one per visit, and under it a line per visit: the calls, cache writes, analytics events and taps that happened while that screen was up, in order. It updates live as the user moves, without pulling the view away from what you are reading.

127.0.0.1:8099

Needs your app to send a screen signal when it navigates. Anything else you send, under any tag, appears on the screen it happened on. A failed call is always shown, never folded away.

Use export ▾ beside the session picker. Each export is one file, holds the whole session with no filter or page limit, and the person you send it to doesn't need Inspector installed.

Production safety

Zero cost in release, and a check that proves it

Release builds swap every module for a no-op twin with an identical API. A canary check then scans your release artifacts and fails the build if any capture code made it in.

Get started

Three steps to your first captured call

Requires Kotlin 2.3.20, Compose Multiplatform 1.11 and Ktor 3. The integration guide covers the rest.

Add the dependency

implementation("io.github.shafichariri:inspector-core:1.3.0")
implementation("io.github.shafichariri:inspector-ui:1.3.0")

Install it and wrap your root

val client = HttpClient(engine) {
    Inspector.install(this)   // add last
}
InspectorOverlay { App() }

Optional: run the daemon for the web UI and MCP

inspector serve          # then open http://127.0.0.1:8099
inspector mcp            # point your agent's MCP config here
Know before you install

What it doesn't do

These limits are deliberate choices, and they're listed here so you don't find them the hard way.

Not process-wideIt sees Ktor and any OkHttp client you hand it. It doesn't see WebViews or native URLSession.
Not wire-levelBodies may already be decompressed. There's no DNS, TLS or TTFB breakdown.
No WebSockets or SSEIt captures request/response traffic only.
Never in productionEnforced by the no-op swap and the canary check above.
